# v0.1 开发计划

## 当前进度

截至当前版本：

- 阶段 2「PDF 文件导入」：**已实现**。
- 阶段 3「PDF.js 本地文本提取」：**已实现**。
- 阶段 1 中的依赖安装、完整测试和构建：需要在可访问 npm registry 的本地环境执行最终确认。
- 下一步进入阶段 4：完善 `invoice-core` 的字段解析准确率与测试覆盖。

## 1. 开发原则

v0.1 按小步迭代完成。

不要一次让 Codex 完成整个版本。

每个阶段：

```text
阅读相关文档
↓
完成一个小目标
↓
运行检查
↓
人工查看代码
↓
提交 Git
```

---

## 2. 阶段 1：确认工程基础

### 目标

确保当前脚手架可以在本地正常运行和静态构建。

### 任务

- `pnpm install`
- 检查 workspace 依赖。
- `pnpm typecheck`
- `pnpm test`
- `pnpm build`
- 本地打开静态产物确认基本页面可用。

### 验收

三个命令全部通过：

```bash
pnpm typecheck
pnpm test
pnpm build
```

### 推荐提交

```text
chore: 完善项目基础配置
```

---

## 3. 阶段 2：PDF 文件导入

### 目标

完成文件选择和拖拽。

### 任务

- 多 PDF 选择。
- 拖拽添加。
- 非 PDF 过滤。
- 文件列表 / 数量状态。
- 处理状态。

### 重点

界面组件只负责文件交互。

不要在上传组件里实现发票解析规则。

### 推荐提交

```text
feat: 完成 PDF 批量导入
```

---

## 4. 阶段 3：PDF.js 本地文本提取

### 目标

从电子 PDF 中读取文本层。

### 任务

- `File.arrayBuffer()`。
- PDF.js 读取。
- 多页循环。
- 合并文本。
- 错误处理。
- 低文本量判断。
- 必要中文学习型注释。

### 推荐模块

```text
apps/web/src/lib/pdf/
```

或现有项目约定的对应位置。

不要把 PDF.js 读取逻辑写入页面组件。

### 推荐提交

```text
feat: 增加 PDF 本地文本提取
```

---

## 5. 阶段 4：完善 invoice-core 解析

### 目标

形成清晰的字段解析流水线。

### 推荐拆分

```text
normalizeInvoiceText()
extractInvoiceNumber()
extractIssueDate()
extractInvoiceAmounts()
parseFilename()
parseInvoice()
```

### 要求

- 每个字段独立处理。
- 正则表达式有中文解释。
- 不可靠启发式只能作为 fallback。
- 未识别字段允许为空。
- 增加单元测试。

### 推荐提交

```text
feat: 完善发票基础字段解析
```

## 12. 不要在本阶段做的事情

如果 Codex 提议以下改动，默认拒绝：

- 引入数据库。
- 引入登录系统。
- 创建 FastAPI 服务。
- 默认上传 PDF。
- 为 OCR 提前进行大规模重构。
- 为“未来可能用到”加入复杂状态管理库。
- 为简单功能引入重量级依赖。
- 在组件中复制一套字段配置。
- 将所有业务逻辑集中到一个页面文件。
