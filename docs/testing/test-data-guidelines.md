# 测试数据使用规范

## 1. 目的

发票包含公司名称、税号、金额等敏感或业务信息。

测试过程中必须避免把真实敏感发票直接提交到公开 Git 仓库。

---

## 2. 不建议提交的内容

公开仓库中不要直接提交：

- 真实公司完整税号。
- 未脱敏发票号码。
- 真实个人姓名。
- 银行账户信息。
- 地址和电话。
- 真实业务金额组合。
- 客户或供应商未公开信息。

---

## 3. 本地真实样本

真实发票可以仅在开发者本地用于验证。

建议建立：

```text
.local-test-data/
```

并加入 `.gitignore`。

真实 PDF 不参与 Git 提交。

---

## 4. 仓库测试数据

自动化测试优先使用人工构造的文本样本，例如：

```ts
const invoiceText = `
发票号码：12345678901234567890
开票日期：2026年08月14日
金额：100.00
税额：13.00
价税合计（小写）：113.00
`;
```

这些数据应明确是虚构数据。

---

## 5. PDF 测试样本

如果未来确实需要把 PDF 测试夹具提交到仓库：

- 使用完全虚构的信息。
- 不由真实发票简单打码后直接提交。
- 文件体积尽量小。
- 在测试数据目录 README 中声明其为虚构样本。

推荐目录：

```text
tests/fixtures/
```

---

## 6. 回归测试

当真实发票暴露一个解析问题时：

1. 不直接提交真实 PDF。
2. 提取导致问题的结构特征。
3. 构造一个不包含真实信息的最小测试文本或测试 PDF。
4. 为该情况增加自动化测试。
5. 修复解析逻辑。

这样既能保护数据，也能长期防止同类问题再次出现。
