# v0.1 大批量性能检查

本清单用于验证 Invoice Workbench 在几十到几百张电子 PDF 发票下仍然保持可用。

## 1. 测试建议

至少准备三档数据量：

```text
50 张
200 张
500 张
```

真实发票只在本地测试，不提交到公开仓库。

## 2. 导入阶段

- [ ] 50 张 PDF 可以完整处理。
- [ ] 200 张 PDF 可以完整处理。
- [ ] 500 张 PDF 不出现浏览器崩溃或页面白屏。
- [ ] 单个文件失败不会阻断后续文件。
- [ ] 处理进度能够持续更新。
- [ ] 处理过程中界面仍可正常滚动。

## 3. Stage 6 批量刷新策略

Stage 6 不再在每解析一张 PDF 后立即重新扫描全部记录计算重复状态。

当前策略：

```text
PDF 顺序解析
↓
结果每 8 条批量刷新一次界面
↓
整个批次完成
↓
统一执行一次重复发票检测
```

这样可以减少大批量文件下 React 重渲染、数组复制和重复状态扫描次数。

验收：

- [ ] 导入过程中记录仍会逐步出现在结果中。
- [ ] 批次结束后重复状态正确。
- [ ] 新批次与旧批次之间的重复号码仍能正确检测。

## 4. 工作台操作

在 200 条以上数据中检查：

- [ ] 搜索输入没有明显卡顿。
- [ ] 状态筛选切换没有明显卡顿。
- [ ] 金额 / 日期排序可以正常完成。
- [ ] 横向滚动流畅。
- [ ] 纵向滚动不会频繁明显掉帧。
- [ ] 打开单张复核后 PDF 可以正常预览。

## 5. 内存与资源

- [ ] 批量导入完成后 PDF.js 文档对象能够释放。
- [ ] 关闭复核面板后当前 PDF Object URL 被释放。
- [ ] 多次切换复核记录后浏览器内存不会持续快速增长。

建议每次性能验证记录：

```text

电脑配置：

```

v0.1 不设置硬性“每张必须多少毫秒”的指标，先以真实办公场景下稳定、可持续操作为发布标准。
