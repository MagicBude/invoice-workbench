# 用户工作流

## v0.1 主流程

```text
1. 打开网站
2. 拖入或选择多个 PDF
3. 浏览器读取 PDF 文本层
4. invoice-core 解析字段
5. 自动执行金额校验与重复检测
6. 表格展示结果
7. 用户修改异常字段
8. 用户勾选需要导出的列
9. 导出 Excel / CSV
```

## 解析状态设计

单个文件至少应有：

- `success`：关键字段完整且校验正常
- `review`：部分字段缺失或校验异常，需要人工确认
- `failed`：PDF 无法读取或未获取有效文本

## 单个异常不能中断整批处理

如果 100 个文件中第 23 个解析失败，其余文件仍应继续处理。

失败记录保留原始文件名，并在备注中显示错误信息，方便用户回查。

## 后续复核模式

P1 版本计划加入：

```text
┌────────────────────┬────────────────────────┐
│ 结构化字段编辑       │ PDF 原始页面             │
│                    │                        │
│ 发票号码            │                        │
│ 开票日期            │                        │
│ 销售方              │                        │
│ 不含税金额          │                        │
│ 税额                │                        │

```

目标是让低置信度结果可以快速人工确认，而不是重新人工抄录整张发票。
