# 单张发票复核工作流

## 1. 目标

批量解析的价值不仅是“尽可能自动识别”，还需要让用户能够快速处理“待复核”和“失败”记录。

Stage 4 增加单张复核面板：

```text
结果表格
  ↓ 点击“复核”
原始 PDF + 完整字段
  ↓
人工修改
  ↓
自动重新校验
  ↓
继续上一张 / 下一张
```

## 2. 本地 PDF 预览

用户首次导入 PDF 后，浏览器会在当前页面生命周期内保留对应的 `File` 引用。

打开复核面板时，仅为当前 PDF 创建临时 Object URL：

```text
File
 ↓
URL.createObjectURL()
 ↓
浏览器 PDF 预览
 ↓
关闭 / 切换
 ↓
URL.revokeObjectURL()
```

这个过程仍然属于本地浏览器处理，不会把 PDF 上传到服务器。

## 3. 字段编辑

复核面板显示完整字段，而不受“显示与导出字段”勾选状态限制。

原因是两种场景目标不同：

- 主表格：用于批量浏览，只显示用户当前关心的字段。
- 复核面板：用于判断某一张发票是否识别正确，需要看到完整结构化结果。

用户在复核面板修改字段后，仍然调用统一的记录更新逻辑，因此会同步触发：

- 金额关系重新校验。
- 置信度重新计算。
- 解析状态重新判断。
- 发票号码重复检测重新计算。
- 后续 Excel / CSV 使用最新值。

## 4. 上一张 / 下一张

复核面板支持在当前批次内直接切换上一张和下一张发票，不需要反复关闭弹窗。

这使大量待复核记录可以形成连续工作流。

## 5. 页面刷新限制

v0.1 尚未引入持久化文件存储。

因此刷新页面后：

- 当前解析记录会消失。
- 本地 `File` 引用会消失。
- PDF 复核需要重新导入文件。

后续如增加 IndexedDB 或本地工作区保存能力，应单独设计隐私与容量策略。
