# v0.1 页面与交互规范

## 1. 设计目标

v0.1 不追求复杂视觉效果。

优先目标：

- 一眼知道如何开始。
- 批量处理状态清晰。
- 表格适合大量数据核对。
- 异常容易发现。
- 操作路径短。
- 桌面端优先，同时保证基础响应式体验。

---

## 2. 页面整体结构

建议单页完成主工作流：

```text
┌────────────────────────────────────────────┐
│ Invoice Workbench                         │
│ PDF 发票批量整理工具                       │
│ 文件默认仅在浏览器本地处理                  │
├────────────────────────────────────────────┤
│ 文件上传区域                               │
│ 拖入 PDF 或点击选择                        │
├────────────────────────────────────────────┤
│ 处理概览                                   │
│ 总数 / 成功 / 待复核 / 失败 / 重复          │
├────────────────────────────────────────────┤
│ 导出字段设置                               │
├────────────────────────────────────────────┤
│ 发票结果表格                               │
├────────────────────────────────────────────┤
│ 合计 / 导出 Excel / 导出 CSV / 清空         │
└────────────────────────────────────────────┘
```

---

## 3. 上传区域

### 默认状态

显示：

```text
拖入 PDF 发票，或点击选择文件
支持批量选择
PDF 默认仅在当前浏览器本地处理
```

### 拖拽状态

当文件拖入区域时：

- 边框高亮。
- 背景轻微变化。
- 显示“松开即可添加”。

### 处理中

例如：

```text
正在处理 12 个文件……
已完成 7 / 12
```

不要让用户误以为页面卡住。

---

## 4. 处理概览

建议使用紧凑统计项：

```text
共 126 张
成功 118
待复核 6
失败 2
重复 3
```

数量为 0 的状态仍可显示，但视觉权重降低。

---

## 5. 导出字段设置

导出字段应分组显示，而不是一长串无结构复选框。

建议分组：

### 文件信息

- PDF 文件名
- 日期
- 名称

### 发票信息

- 发票类型
- 发票号码
- 开票日期

### 购销方

- 销售方名称
- 销售方税号
- 购买方名称
- 购买方税号

### 金额

- 不含税金额
- 税额
- 价税合计
- 税率

### 其他

- 项目名称
- 备注
- 解析状态
- 置信度
- 重复状态
- 金额校验

提供：

```text
全选
恢复默认
```

不建议加入“全不选后仍可导出”的行为。

至少应保留一个字段。

---

## 6. 表格

### 基础要求

- 表头固定。
- 表格横向可滚动。
- 表格适合宽屏。
- 行悬停高亮。
- 可编辑字段使用输入控件。
- 金额列右对齐。
- 日期和编号保持不换行优先。
- 文件名过长时允许截断，但能够查看完整值。

### 状态展示

建议：

```text
成功
待复核
失败
重复
金额异常
```

使用图标、徽标或轻量背景辅助区分。

不要只依赖颜色表达重要状态。

---

## 7. 用户编辑

用户修改单元格后：

- 立即更新当前记录。
- 如果修改金额，重新执行金额校验。
- 如果修改发票号码，重新执行重复检测。
- 汇总金额重新计算。
- 导出时使用修改后的数据。

---

## 8. 删除记录

每行提供删除入口。

点击后：

- 从当前列表移除。
- 更新总数。
- 更新重复检测。
- 更新金额合计。

对于单行删除不强制弹确认框。

“清空全部”必须二次确认。

---

## 9. 空状态

没有数据时显示明确说明：

```text
还没有发票数据
拖入或选择 PDF 文件开始整理
```

不要只显示空白表格。

---

## 10. 失败状态

单个文件失败时保留一行记录，至少包含：

- 文件名。
- 解析状态。
- 错误原因。

例如：

```text
解析失败：无法读取 PDF
```

这样用户能够知道是哪一张文件有问题。

---

## 11. 导出操作

页面主操作：

```text
导出 Excel
```

次级操作：

```text
导出 CSV
```

当列表为空时按钮禁用。

当没有选择任何导出字段时按钮禁用，并给出说明。

---

## 12. 响应式策略

本项目主要用于桌面端批量整理发票。

因此优先级：

```text
桌面端 > 平板 > 手机
```

手机端不要求完整展示所有表格列，可以通过横向滚动完成基本操作。

---

## 13. 可访问性

基础要求：

- 按钮有明确文本。
- 输入元素有可理解标签。
- 状态不只依赖颜色。
- 键盘可以访问主要操作。
- focus 状态可见。
