# 本地优先架构

## 核心定义

Local-first（本地优先）在本项目中表示：

> 默认工作流中，原始发票 PDF 不离开用户设备。

## 数据路径

```text
本地 PDF
  ↓
Browser File API
  ↓
ArrayBuffer
  ↓
PDF.js
  ↓
文本
  ↓
invoice-core
  ↓
InvoiceRecord[]
  ↓
表格 / Excel / CSV
```

## 浏览器持久化策略

v0.1：

- 不持久化原始 PDF。
- 不持久化 PDF 全文。
- 导出字段偏好可以写入 `localStorage`。
- 表格数据默认只在当前页面会话内存在。

后续可以评估 IndexedDB，用于支持“刷新页面后继续工作”，但必须提供明确的数据清除入口。

## 云端能力规则

未来增加 OCR / AI 时必须满足：

```text
本地解析失败或置信度较低
      ↓
提示具体原因
      ↓
用户主动点击“使用云端 OCR / AI”
      ↓
明确提示上传行为
      ↓
只上传用户选中的文件
```

禁止：

- 页面加载后自动上传
- 本地解析失败后静默上传
- 默认保存原始发票

## 性能意义

本地优先还能降低：

- 带宽成本
- API 成本
- 服务器 CPU 成本
- 文件队列压力
- 隐私合规复杂度

局限是浏览器处理能力有限，因此大批量场景需要通过 Web Worker、分批处理和进度反馈进行优化。
